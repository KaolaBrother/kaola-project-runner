# Finalization Summary — Issue #173

## Delivered

A Codex Host turn that ends in `threadStatus systemError` (a failed remote compact)
is now recorded `turn_failed` instead of `turn_completed/end_turn`, and the worker
events that turn delivered stay staged (unconfirmed) for redelivery instead of being
confirmed and dropped.

Spec: the owner-mandated diagnosis comment
https://github.com/KaolaBrother/kaola-project-runner/issues/173#issuecomment-5842433240

The fix is confined to `scripts/kaola-acp-holder.py` and follows the diagnosis exactly:

1. `on_session_update` — a **separate `if`** after the variant chain (deliberately not a
   new `elif`, which would stop `session_info_update` counting as an unknown update and
   change healthy receipts). During an active turn of this session, a
   `_meta.codex.threadStatus` of `systemError` sets
   `turn["error"] = {"code": "agent-system-error", "threadStatus": <status>}`; any other
   status sets it to `None`, so the last status in the turn wins and a recovered turn
   stays healthy.
2. `on_prompt_response` — in the branch without a transport error, the outcome is
   `turn_canceled` if `cancelled`, else `turn_failed` if `turn["error"]` is set, else
   `turn_completed`. `stop_reason` stays verbatim (`end_turn`) per the #113 contract.

`_empty_turn` gained an `"error": None` key so every turn carries the field from the start.

Everything downstream reuses existing machinery: `turn_ended` records `turn_failed`; the
existing failed-turn path in `_worker_event_turn_end` leaves the delivered events staged
and clears their delivery mark (no retry loop); `status`/`observe` report
`turn_outcome: turn_failed`; `send`/`wait` receipts attach `turn["error"]`.

Explicitly not done, per the diagnosis's anti-recommendations: `fatal_error` is not
reused; `willRetry` `codex.error` reconnect attempts do not fail a turn; no new status
field was added; the AIR typed-failure capability is not advertised to the adapter; no
immediate redelivery retry was added. The issue's Secondary note
(`session_meta.models.currentModelId` staleness) was split out and not touched.

- the reported defect: systemError + `end_turn` → `turn_failed`, event stays staged and
  unmarked, no `worker_event_confirmed`;
- the typed error rides `turn_receipt()` as `error.code: agent-system-error`;
- the staged event redelivers at the next healthy boundary and is then confirmed;
- `op_state().turn_outcome == "turn_failed"`;
- idle control: healthy `active`/`idle` is `turn_completed` with no `error` key;
- a turn that recovers (systemError then idle) stays healthy;
- a `willRetry` reconnect does not fail a turn;
- a child-session thread status cannot fail the parent turn;
- a status outside any turn is inert;
- `session_info_update` still counts as an unknown update (the `if` vs `elif` contract).
