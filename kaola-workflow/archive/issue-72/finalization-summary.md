## Delivered

Every new issue-backed ACP worker dispatch picks its real open GitHub issue before starting
anything and names the Runner session `<platform>-<PROJECT>-i<ISSUE>-<unique-purpose>`, where
`PROJECT` is the stable ASCII short code the consuming project's rendered heartbeat declares
beside its canonical repository identity. Field order and the literal `i` delimiter are fixed;
an issue is never read out of the purpose token or any other substring; the name is verified in
the start receipt and reused on later heartbeat dispatches and same-issue restarts.

One Workflow run claims one real issue — no bundle claim, branch, child worktree, Mission List,
or Runner session spans several — while several workers may collaborate on the same issue and
share that issue run's Mission List under distinct names and distinct native sessions. The
orchestrator Host itself, transport-only diagnostics, and genuinely issue-less tasks carry no
issue number, and none is invented.

Control-plane scheduling policy only. The nine worker Skills gained no classifier, the existing
1–80 `--session` syntax stays the single validator, no registry, daemon, or Workflow state field
was added, no byte budget was raised, and running sessions — including names predating the rule —
are neither renamed nor restarted to adopt it.
