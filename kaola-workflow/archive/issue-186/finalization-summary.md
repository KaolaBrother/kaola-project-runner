# Finalization Summary — Issue #186

## Delivered

A fresh Claude Code ACP seat now publishes the resumable native Claude session id, so
`start --resume <native id>` and `drain-restart --resume` work for seats that began fresh.

Root cause (per the issue): a fresh seat's only Runner-visible id was the bridge-minted 32-hex
`acp_session_id`, which is process-local and never resumable; the native Claude UUID was learned
only after the first turn and kept inside the bridge. After a `stop` the recorded `acp_session_id`
could only ever fail `resume-failed`.

The vendored bridge (`vendor/claude-code-acp/src/agent.ts`) now emits one credential-free
`native_session_identity` session update in the ZCode shape
(`{"sessionUpdate":"native_session_identity","acpSessionId":<acp id>,"nativeSessionId":<claude uuid>}`):

- on a seat's first turn — fresh, resumed by native id, or cancelled;
- on the fresh conversation a resume-failure fallback starts;
- de-duplicated against the last id this process announced (a repeated turn stays silent);
- the cancel path announces the id in force, the announced id first, so a cancelled fallback turn
  reports its new conversation V rather than the U its resume had already failed to reach;
- an empty id never clears an existing binding (the continue path can reach the binder with none).

The holder already records `session/update`, so `capture` exposes the event exactly as for ZCode
`sess_*`; no holder change was needed. Where a seat emits more than one identity event, the newest
`nativeSessionId` wins, because a fallback replaces the conversation. The bridge log masking
(`maskId`) is untouched — the raw id still never reaches a bridge log line; it now travels in the
seat's `events.jsonl`, the same exposure ZCode `sess_*` already has (confirmed acceptable by the
issue). `dist/` was rebuilt via `kaola-dist.py --write` and `UPSTREAM.md` item 4 updated.

Documentation travelled through templates and `render-skills.py --write`:
`templates/orchestrator/references/host-startup.md.tmpl` (Claude Code clause, the resume-bound
`acp_session_id = U` rule, the newest-event rule) and `platforms/claude-code.yaml` `acp_quirks`.
