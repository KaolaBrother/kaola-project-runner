## Delivered

Two release-review defects, both prompt/evidence level.

**1. The permission default is stated per platform.** The generated main Skill's `Defaults` table
said "Existing Runner default bypass start", which reads as a guarantee across all nine platforms.
Derived from the manifests, it is not one:

| class | platforms | evidence |
|---|---|---|
| advertised ACP skip-all option at start | claude-code, codex, devin, kimi-cli, zcode (`mode`), droid (`autonomy_level`) | `acp_mode_config_id` non-empty |
| launch flag only, no advertised option | cursor-cli (`--yolo`), grok (`--always-approve`) | `acp_command` carries the flag, `acp_mode_config_id` empty |
| no ACP skip-all at all | opencode | `opencode acp` takes no skip argv; PTY `--auto` is the only bypass |

The row now reads `Per platform, not one global bypass.` and the surrounding paragraph states one
general rule rather than naming a platform: `With no verified ACP skip-all, permission may still
arise: permit settles it, never force PTY or add a gate.` "May", not "will" — a launch flag can
still suppress the request and nothing measured otherwise. The request surfaces through the
existing `permission_required` carrier event (Issue #76) and is settled with the existing `permit`
op. No auto-approval, no new gate.

**2. OpenCode's steering evidence carries its own version, consistently.** The manifest declared
`acp_verified_versions cli=1.18.29` while `steering_summary` reported a JSON-RPC `-32601` probe
actually run on 1.18.17. `native_steering` is now `unknown` rather than `unsupported`, so three
surfaces agree: the 1.18.17 result stays in the summary as explicit history; `render-skills.py`
gained a third steering block whose worker-Skill wording is "no native entry has been **verified**
… not a proven absence"; and `kaola-acp.py`'s two refusal messages reword only the unknown case,
adding "absence is not established". `unknown` was already a first-class manifest value and receipt
outcome — only the wording that contradicted it changed.

No release doc pins a native-steering roster or count any more: both `README.md` and `docs/api.md`
send the reader to `native_steering` in `platforms/<id>.yaml`, so Issue #81's ZCode work cannot
falsify either page.
