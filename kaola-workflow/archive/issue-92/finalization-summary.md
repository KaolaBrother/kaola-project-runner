## Delivered

A `permission_required` wake raised while the bound ZCode Host holder is unreachable is no longer
lost. Measured at the base `aa5fdad`: 90 s after the *same* authorized Host restarted it had zero
staged events, zero prompts, and the worker was still blocked with `turn_active: true`
(`evidence/01-baseline-loss-probe.log`).

The worker holder now retains the undelivered event and re-offers it from the holder's **existing
15 s `idle_watcher` tick** — no new thread, loop, scheduler, registry, ledger, or transport gate,
and no attempt cap or expiry: the wake lives exactly as long as the request it locates. The retry
re-sends the original params, so the deterministic `event_id` is unchanged and a repeat meets the
existing Issue #90 dedup rather than prompting twice or asking for a second approval.

Two facts are kept apart, which is the substance of the last three review rounds:

- **Owed** means the Host never took the event — `host-unreachable`, `host-closed`,
  `host-reply-invalid`, `unknown-op`. Any receipt the Host produced settles it, refusal included.
  An accepting receipt must name the **exact** `event_id` that was sent.
- **Delivered is not approved.** Staleness is re-read immediately before the socket write, so a
  settled request, exited agent, or begun stop aborts that offer. That narrows the window and does
  not close it: a settlement landing after the write leaves the Host holding a locator for a gone
  request, recorded as `heartbeat_carrier_delivered_stale` with the reason and the Host's own
  receipt — never as `heartbeat_carrier_recovered`. Safety is on the Host side: the event is a
  locator, the Host re-reads live `pending_permissions`, ignores a vanished request idempotently,
  approves nothing from the event, and a stale approval is refused with `no-pending-permission`.

Ordinary `idle`/`terminated` stay one-shot; unbound workers and non-ZCode Hosts are unchanged;
nothing auto-approves; only the locator travels.
