## C 触发与载体

**触发方**各不相同，由各宿主既有机制决定：

- **Codex**：由 Codex 自己的定时系统按心跳间隔（默认 30 分钟，除非另有指定）触发，把这篇工作提示词投递给我。
- **Grok Bot**：由本 Bot 主会话上的**一条 Routine**（该宿主唯一的心跳载体）按定时触发投递；不得与 Codex heartbeat、其他 loop 或阻塞 sleep 叠用。
- **ZCode Host**：**事件驱动，没有 Routine / cron / sleep**。它在每次 worker 启动时导出 `KAOLA_ACP_HEARTBEAT_HOST`，之后每一次 worker 终止或 turn-end idle 触发一次完整心跳投递；没有 worker 事件就没有触发。

**不是同一个文件实现**。三者是同一篇工作提示词落在各自宿主既有载体上，不要求同路径、同 schema：ZCode Host 写项目根 `.kaola/heartbeat-prompt.json`（JSON 对象，整篇提示词放在非空字符串字段 `body` 里；字段名写错或为空，投递出去的就是一条明确的缺失报告而不是提示词）；Codex 和 Grok Bot 则各自更新其定时系统里已有的提示词载体。不给 ZCode 加定时器，也不把 Codex / Grok Bot 改成事件触发，更不为此新建 schema 或调度器。
