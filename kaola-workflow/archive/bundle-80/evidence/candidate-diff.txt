    test(issue-80): disable detached git auto-maintenance in fixtures
    
    git >=2.47 spawns `git maintenance run --auto --quiet --detach` after
    commit/merge/rebase (and receive-pack after push). The detached child
    runs `repack --write-midx` + update-server-info inside the fixture .git
    while TemporaryDirectory teardown rmtree's it, making
    test-issue-49-grok-bot-host.py die in cleanup with Errno 66 on
    repo/.git after all 43 assertions pass — and taking validate.sh's
    lane B down with it.
    
    Fixtures never need background maintenance: set maintenance.auto=false
    via GIT_CONFIG_* env in git() for direct children, and
    receive.autogc=false in the bare origin's own config because push
    strips GIT_CONFIG_* before spawning git-receive-pack. gc.auto=0 does
    not gate this spawn; neither knob masks the symptom.
