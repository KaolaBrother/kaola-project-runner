# Outer resolution of Opus node-design decisions — #255

Source: owner-authorized design refinement; `sideagent-node-refinement.md` and `sideagent-nodes-review.md`. Please reconcile only these decisions, not another baseline review. Compatible repairs and QA continue. No release/install. Implementation of node mode follows the settled issue specification.

## Agreed and resolved

1. **I-1: accept a sourced Host business write as the trigger.** The Host records its task/needs/verdict or changed owner constraint once through the existing state tool; the tool derives `host_revision`. This is its business decision, not a requirement to manage node counters, processes, holds or cleanup. Sideagent continues all procedural maintenance. A helper may transcribe a named Host turn when appropriate, but transcription is no longer required before a cold node can be triggered. Replace that narrow default in old design §4/review point4, not all role boundaries. Compare pending Host revision with the revision acknowledged by a verified node checkpoint, not merely last given to a started node; failed admission cannot consume a request. A concurrent later Host write remains pending. No node on every generic Host turn, no second request queue.

2. **C-1: scoped project-contract exception is authorized by this owner direction.** Add a narrow AGENTS exception: only a Host-role carrier, with supported node capability and an explicitly adopted active bound Sideagent recipe in node mode, may mechanically invoke the existing exact start/stop for that role and carry its node events. Standalone Platform Runner transport, normal workers, grant/model decisions and project acceptance remain unchanged. Never arbitrary shell evaluation. The exception belongs in project-owned contract text, not a weakened global Workflow contract. User has already authorized this design; do not ask again for the same scope.

3. **I-4/I-5 accepted.** The role recipe includes the existing index locator; current node identity/result stay in existing carrier records and current checkpoint. Move node-specific guidance into one progressively loaded reference and replace obsolete paragraphs; do not append full protocol to Host entry or duplicate manuals. Keep the HTML artifact aligned through the sole implementation owner.

4. **Fresh native identity; stable role identity.** A stable Sideagent role name may be reused as proposed, with a new holder and native conversation every node. This is a scoped Sideagent-role convention only; ordinary workers still get a new standard session for a new assignment. All stop, checkpoint, relay confirmation and late-write checks bind the exact node/holder, never a name alone. Process preservation must prove each protected worker via recorded dispatcher/worker identity and live start-time facts; if an earlier node's worker must be recognized, use its recorded historical dispatcher/receipt, not a broad `(runtime, session, repo)` match that claims ownership over any same-named incarnation. Keep the spawn-record and exact record-backed evidence union, preserving ZCode's existing environment boundary.

5. **Checkpoint is explicit and source-correlated.** End-turn is only a signal to inspect it. The checkpoint must account for the fixed batch's inputs by references to applied records, retained waiting/unknown duties or escalated decisions/alerts. A referenced existing file alone, an empty refs list, or a checkpoint for another batch cannot settle unaccounted inputs. Mechanical verification checks the batch/holder/revisions and coverage links, not whether the project work is correct. A known task wait can complete the maintenance node while the task remains open. An omitted input remains recoverable and cannot be silently acknowledged. No duplicated mission ledger; use existing batch/event identities and current checkpoint.

## One substantive adjustment to the proposal

**I-3: no blanket rule that any failed node requires a Host LLM binding rewrite.** This would reintroduce the maintenance duty the owner explicitly removed. Use an unresolved lifecycle outcome in the existing carrier, return/retain all unconfirmed inputs and expose a durable warning. Reconcile start/send/checkpoint/stop receipts at existing boundaries; verified completion may close an uncertain action. Do not cold-start repeatedly against the same unresolved failure or a known hold. Confirmed service/auth/adapter refusals keep the existing on-hold and no-login/user-decision rules. For cases not mechanically resolvable, Delegator supervises the existing recovery route; Host direct recovery remains available as an exception, not the routine obligatory re-arm. The Host receives project impact/decision needs, not maintenance internals. Other workers and unrelated project work continue.

A bounded checkpoint correction in the same unfinished node may be used as proposed (one explicit reminder), but no unbounded retry, fresh-node storm or mandatory new timer. Node failure itself does not silently authorize another model. If explicit re-arm is needed, the existing lifecycle recovery operation must identify the cause/evidence and responsible controller; normal business writes must not implicitly clear authentication/quota holds.
