Stage-one verdict: **RED — adoption acceptance incomplete** (2026-10-31); see the continued-run results below. Owner requires the latest relevant adapter to pass before adoption; existing basic communication is not sufficient. Do not interpret this as proof that currently running sessions are broken. Do not change the adapter pin on this evidence.

## Upstream and current contract

The npm `latest` tag was adapter 2.5.0 (preview 2.5.1-preview.11), and CLI 0.166.0. Adapter 2.5.0 declares `@openai/codex: ^0.165.0` and `@agentclientprotocol/sdk: ~2.1.0`; under npm pre-1.0 caret semantics, 0.166.0 and 0.162.1 are outside that declared range. The [2.5.0 changelog](https://github.com/agentclientprotocol/codex-acp/blob/v2.5.0/CHANGELOG.md) records v2, structured failures, foreground state, and compact settlement in 2.3; standard subagent sessions and host-owned idle-steer fallback in 2.4; SDK 2.1 alignment in 2.5. These are upstream claims, not KPR acceptance.

Manifest impact: keep absolute `CODEX_PATH` selection, invalid path refusal and distinction between adapter dependency and actual child; an adapter bump alone does not pin a CLI. The protocol-1 initialize path still works in observed samples. Empty capability objects remain advertised; 2.5.0 additionally advertises `systemPrompt`. All four mode IDs remain advertised; mode selection is a turn config, distinct from the initial `session/new` mode snapshot. Observed read-only approval and workspace-write behavior are below; full-access and auto-review are configuration readbacks, not exhaustive sandbox proof. Existing tool-call parsing handled observed read/execute and parent subagent tool events. Compaction completion was observed before turn settlement and reload admission. Busy steering worked, while KPR refused an idle steer before calling the adapter; the new upstream idle fallback is not thereby tested. Structured v2 failures, foreground state, v2 negotiation and independent standard child-session event consumption remain unverified. Do not silently delete the protocol-1, sandbox or identity quirks on the basis of the changelog.

KPR initializes `clientCapabilities` with `session.compaction`, not top-level `subagents`. The installed 2.5.0 adapter source's `subagentProtocol` selects `hidden` for this protocol-1 non-AIR capability set. In a real subagent turn the KPR log contained parent `tool_call` start/completion events and the child answer, but no standard `subagent_update` or independent child-session event. The holder currently appends message and tool updates to the active turn without consistently filtering foreign session IDs. This is a concrete acceptance gap, not proof of a reproduced corruption: the source path is dormant for the observed hidden-child negotiation. Next -dev patch: determine the intended standard child-session exposure and safe session-scoped projection/permissions, add focused real and contract tests that exercise child IDs and parent isolation, and validate the actual generated candidate. Preserve protocol-1 communication and do not add a version gate. Independently exercise the upstream idle fallback with a controlled direct ACP client and decide whether the existing explicit idle refusal remains the desired KPR behavior.

Re-check latest upstream at adoption time. Until those checks pass, the requested green and verified version update are not established.
