## Actual gateway interfaces

**[SOURCE_VERIFIED]** The implementation is [`ee/apps/den-api/src/mcp/agent.ts`](https://github.com/different-ai/openwork/blob/e7d03dd431342307c26c9568d0049d5f948fd846/ee/apps/den-api/src/mcp/agent.ts#L441-L507): `registerAgentMcpRoutes` handles `/mcp/agent`, verifies the MCP request, resolves the member, and builds a member-scoped capability context. It registers `search_capabilities` with `query`, bounded `limit`, source `type`, and optional `intent`; the handler searches the registry and returns shaped matches ([lines 682–720](https://github.com/different-ai/openwork/blob/e7d03dd431342307c26c9568d0049d5f948fd846/ee/apps/den-api/src/mcp/agent.ts#L682-L720)). `execute_capability` accepts the exact returned `name`, optional `schemaDigest`, `path`, `query`, and `body`, then delegates to `executeCapability` ([lines 722–782](https://github.com/different-ai/openwork/blob/e7d03dd431342307c26c9568d0049d5f948fd846/ee/apps/den-api/src/mcp/agent.ts#L722-L782)).

**[SOURCE_VERIFIED]** The shared [`capability-registry.ts`](https://github.com/different-ai/openwork/blob/e7d03dd431342307c26c9568d0049d5f948fd846/ee/apps/den-api/src/mcp/capability-registry.ts#L818-L894) searches seven sources concurrently—OpenAPI catalog, native APIs, external MCPs, marketplace, built-in skills, remote sessions, and admin—and merges/ranks their matches. Execution parses the exact capability name and dispatches to its owning source. The endpoint also registers direct `list_skills` / `get_skill` and skill-creation tools; they are not forced through the search+execute pair ([agent.ts lines 785–815](https://github.com/different-ai/openwork/blob/e7d03dd431342307c26c9568d0049d5f948fd846/ee/apps/den-api/src/mcp/agent.ts#L785-L815)). `type: "connectors"` returns a legacy setup-catalog envelope directly, not callable capability matches ([agent.ts lines 702–718](https://github.com/different-ai/openwork/blob/e7d03dd431342307c26c9568d0049d5f948fd846/ee/apps/den-api/src/mcp/agent.ts#L702-L718)).

## OpenCode reuse

**[SOURCE_VERIFIED]** The desktop server starts `opencode serve` ([`managed-opencode.ts`](https://github.com/different-ai/openwork/blob/e7d03dd431342307c26c9568d0049d5f948fd846/apps/server/src/managed-opencode.ts#L150-L191)). Its server-managed `OPENCODE_CONFIG` includes the runtime MCP map ([`openwork-runtime-config.ts`](https://github.com/different-ai/openwork/blob/e7d03dd431342307c26c9568d0049d5f948fd846/apps/server/src/openwork-runtime-config.ts#L5-L18), [lines 120–123](https://github.com/different-ai/openwork/blob/e7d03dd431342307c26c9568d0049d5f948fd846/apps/server/src/openwork-runtime-config.ts#L120-L123)). Local skill discovery reads `.opencode/skills/<name>/SKILL.md` and `~/.config/opencode/skills`, alongside Claude/Agent skill directories ([`skills.ts`](https://github.com/different-ai/openwork/blob/e7d03dd431342307c26c9568d0049d5f948fd846/apps/server/src/skills.ts#L188-L217)). Connect’s server catalog turns exposed remote connections into OpenCode `type: "remote"` MCP entries and reconciles them into that runtime map ([`connect-mcp-server-catalog.ts`](https://github.com/different-ai/openwork/blob/e7d03dd431342307c26c9568d0049d5f948fd846/apps/server/src/connect-mcp-server-catalog.ts#L220-L235), [lines 401–447](https://github.com/different-ai/openwork/blob/e7d03dd431342307c26c9568d0049d5f948fd846/apps/server/src/connect-mcp-server-catalog.ts#L401-L447)). The OpenCode reuse is config/directory compatibility; capability cataloging and connector reconciliation are OpenWork code.

## License partition
