## Part F — Self-evolution mechanism design (design only)

A closed loop over **existing** structures — no new framework, per the AGENTS #5 no-self-modification-engine rule:

1. **Surface**: symptoms already arrive via Runner receipts, typed heartbeat alerts/decisions, state check, Delegator inquiry, the post-release consumer-bridge observation duty, and independent audits like this one. A "missed item" = a symptom whose root cause pins to a KPR surface gap. No new monitor.
2. **Root-cause classification (Host judgment)**: pin each symptom to source + original evidence + causal boundary (Part C method); classify doc gap | schema gap | tool gap | consumer usage deviation | environment, then map to the QA classes of Part D. A single incident never becomes a hard gate.
3. **Minimal improvement formation (Host)**: smallest-sufficient change per confirmed root cause (Part E pattern), budget-aware, deduped against published issues (#267 boundary below).
4. **Independent verification**: a different seat re-verifies claims against original evidence; affected suites via --suite; live ACP smoke when transport is touched; owner-appointed independent reviewer (Fable/dot) for schema deltas (D4).
5. **Adoption**: templates -> render-skills.py --write -> --check -> affected suites -> CHANGELOG (Seats: restart required/not; operator test) -> pinned release; consumers migrate via existing state migrate + install-verify receipts; stale: true detection already forces seat reload at safe boundaries.
6. **Retrospective recurrence**: (a) every text fix carries its own static oracle, so each future suite run re-asserts the fix — in-gate, no ledger; (b) behavioral recurrences (usage deviations) are reported to the owning bridge under the existing post-release observation duty (read-only snapshot diffs after actual Host business updates); (c) an unresolved unclassified matter stays on the existing decision/reconciliation route.
7. **Rollback**: text/oracle changes revert by Git revert of the template commit + re-render, budget-safe by construction; D4's schema addition is default-absent (unknown keys -> unverified for older readers, verified at adoption) so rollback needs no data migration; state migrate plan-mode-first already guards torn migrations.

**Boundary map.** Automatable (machine): render --check, byte budgets, static doc oracles, --help content oracle, schema validation, suite runs, install-verify diffs, read-only recurrence diffs, hash/revision pins, stale-seat detection.
