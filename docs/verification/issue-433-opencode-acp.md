# Issue 433: OpenCode ACP upgrade — partial evidence, not accepted

Baseline: `b353f3d80beae67d3495018fe01d698c256fbfce`. The owner requires newest-ACP verification and the six-proxy-key stripping contract before adoption. The latter is not present in this baseline: `scripts/kaola-acp.py:agent_environment` copies `os.environ`, and `scripts/kaola-launchd-broker.py:filter_env` includes `PASS_PROXY`. OpenCode is in `LOOPBACK_NO_PROXY_PLATFORMS`. No conclusion about an integrated stripping implementation follows from this run. Do not mark 2.2.5 verified or adopt it from this evidence.

## Upstream

The npm `@opencode/cli` latest was 2.2.5 on 2026-10-31; its native `opencode acp` is the upstream adapter tested, not the unrelated `opencode-ai` package. [V2 changelog at v2.2.5](https://github.com/anomalyco/opencode/blob/v2.2.5/CHANGELOG.md) documents local service proxy bypass in 2.2.4 and `bash` to `shell` mapping in 2.2.5. These statements do not establish KPR behavior. Comparison of the upstream v2.0.22 and v2.2.5 ACP files shows changes to permission, config-option, catalog, sessions, turn, and connection. In particular permission changes from promise client/event types to effect client and typed schemas, adds child-session tool identity, and moves request/reply handling; config and catalog use typed model/provider references and changed reload/selection logic; session and turn attachment, event, permission and cancel handling changed. Source changes alone do not establish a defect.
